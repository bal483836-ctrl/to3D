# 接入真实混元 3D + 图文联合条件生成方案

本文说明如何把 M1 的 Mock 换成**真实混元 3D 推理服务**，并把「图文联合条件生成」
落到实处。上层编排、六维自检、前端**均无需改动**——只需实现一个满足约定接口的
推理服务，并设置 `TO3D_ADAPTER=http`。

---

## 1. 总体接入方式

```
本仓库(编排/自检/前端)  ──HTTP──►  你的混元 3D 推理服务(GPU)
   HttpHunyuan3DAdapter                - 条件编码(图像 DINO/CLIP + 文字 CLIP)
   (backend/app/adapters/http.py)      - Hunyuan3D-DiT (联合条件形状生成)
                                        - Hunyuan3D-Paint (联合条件纹理生成)
```

启用：
```bash
export TO3D_ADAPTER=http
export TO3D_HUNYUAN_ENDPOINT=http://your-hunyuan3d:9000
```

适配器已按下述约定实现 HTTP 调用，见 `backend/app/adapters/http.py`。

---

## 2. 推理服务需实现的端点约定

### 2.1 `POST /generate` — 图文联合条件生成（核心）
请求：
```json
{
  "images": [{"view":"front","url":"...","required":true}, ...],
  "prompt": "青花瓷花瓶, 细长颈, 圈足, 缠枝莲纹, 釉面高光",
  "image_scale": 1.0,
  "text_scale": 0.35
}
```
响应：
```json
{
  "glb_base64": "....",             // 或 "mesh_url": "https://..."
  "texture": {                      // 供六维自检的语义/材质描述
    "patterns": ["缠枝莲"],
    "glossy": true,
    "metalness": 0.0,
    "roughness": 0.12
  }
}
```
服务端要点见 §3。

### 2.2 `POST /reference` — 规格重建（仅自检用，不交付）
请求 `{"prompt": "..."}`，响应同 `/generate`。用于度量联合产物在几何/材质上的偏离；
生产环境也可用输入图像做多视角轮廓/CLIP 比对替代它。

### 2.3 `POST /refine` — 几何定向修正
请求 `{"focus":["bottom"],"prompt":"..."}`，响应含新 mesh。语义：提高该维度文字引导后
局部重生成。

### 2.4 `POST /repaint` — 纹理/材质重绘
请求 `{"focus":["pattern","material"],"prompt":"..."}`，响应含新 `texture`。
对应 Hunyuan3D-Paint 按文字约束重绘。

> 以上响应里的 `texture` 描述，生产环境应由服务端对生成贴图运行 CLIP/VQA(花纹存在性)
> 与 PBR 统计(金属度/粗糙度)得到，回传给自检引擎。

## 3. 「图文联合条件」在混元 3D 内部怎么做

原生 Hunyuan3D-2/2.1 以**图像条件**为主（DiT 的 cross-attention 条件来自图像编码器
DINOv2 提取的 patch tokens）。要实现**图文同时**作为条件，推荐以下路线（按落地成本递增）：

### 路线 A（最小改动，推荐先做）：条件序列拼接 + 双模态 CFG
1. **图像分支**：多视图分别过图像编码器(DINOv2)得到 patch tokens，拼接为
   `img_tokens ∈ R^{(V·N)×d}`（V=视角数，N=每图 token 数）。
2. **文字分支**：prompt 过文本编码器(CLIP text / T5)得到 `txt_tokens ∈ R^{L×d'}`，
   经一层可训练投影 `Linear(d'→d)` 对齐维度。
3. **拼接条件**：`cond = concat(img_tokens, txt_tokens)`，加上模态类型嵌入(区分图/文)，
   作为 DiT 每个 block 的 cross-attention KV。
4. **双模态 CFG**：训练时对 `img_tokens`、`txt_tokens` **各自独立随机 dropout**（各 ~10%）。
   推理时组合三/四路无分类器引导：
   ```
   eps = eps(∅,∅)
       + image_scale · [eps(img,∅)  - eps(∅,∅)]
       + text_scale  · [eps(∅,txt)  - eps(∅,∅)]
   ```
   `image_scale/text_scale` 即本产品的「模态引导权重」滑块。
5. **纹理**：Hunyuan3D-Paint 的条件同样拼接图像 + 文字（或先用文字精修多视角贴图 prompt）。

> 只需训练：文本投影层 + cross-attention 中新增文字 KV 的适配权重（其余可冻结），
> 属于轻量 **adapter 微调**，无需从头训练 DiT。

### 路线 B：Text→多视角图 与 输入图 融合后再联合
当自有文字条件数据不足时，用文生图(可控多视角)把文字转成参考视图，与用户上传视图
一起送入 Hunyuan3D-MV；文字同时经路线 A 的文字分支注入。兼顾可控性与还原度。

### 路线 C：几何 + 语义分工的联合
DiT 主要吃图像(几何)，文字经 §2.3/§2.4 的 refine/repaint 与"不可见区域先验"注入。
这是 M1 Mock 目前模拟的近似语义，可作为无联合训练时的兜底。

## 4. 训练要点（路线 A adapter 微调）

- **数据**：三元组 `(多视图图像, 文字描述, 3D 资产)`。文字可用 VLM(如 Qwen-VL)对资产
  多视角渲染自动打标(器型/材质/纹样/比例/底部)，再人工抽检。
- **可训练参数**：文本投影层、文字 KV 适配、模态类型嵌入；DiT 主干与图像编码器冻结。
- **损失**：沿用 DiT 的 flow-matching / 扩散损失；建议加**模态一致性正则**——对同一样本
  分别以纯图、纯文、图文联合条件采样，约束联合结果同时靠近两模态目标。
- **CFG dropout**：图/文各自独立 dropout，保证推理期双模态引导可分别调强弱。
- **评测**：直接复用本仓库六维自检作为离线指标(器型 Chamfer、比例、底部、花纹 CLIP、
  材质 PBR)，跟踪 overall 与各维通过率。

---

## 5. 部署形态

- **推理服务**：单独 GPU 服务(建议 A100/H800 级)，vLLM/自研 server 暴露 §2 端点；
  显存不足时形状与纹理分两个副本。
- **本仓库**：无状态，CPU 即可，负责编排/自检/前端；水平扩展。
- **存储**：mesh/贴图入对象存储，任务与报告入 PostgreSQL，条件编码可缓存(Redis)。
- **超时**：`TO3D_REQUEST_TIMEOUT` 覆盖长耗时生成。

---

## 6. 联调自检清单

1. `curl $ENDPOINT/generate` 手测能返回 `glb_base64` 或 `mesh_url` + `texture`。
2. 本仓库设 `TO3D_ADAPTER=http` 起服务，`/api/health` 显示 `adapter=http`。
3. 前端跑一单：观察 `generating → verifying → refining → done`，六维报告与 3D 预览正常。
4. 调「模态引导权重」，确认结果随 image_scale/text_scale 变化(几何/纹理侧重不同)。
