# 多图 + 文字联合驱动的 3D 模型生成产品方案设计

> 目标：基于**混元 3D（Hunyuan3D）**，实现「同一份 3D 模型由多张图片与一段文字**同时（联合）**驱动生成」。核心是**图文联合条件生成（单次，一份模型）+ 六维一致性自检 + 定向修正闭环**。

---

## 1. 产品目标与核心价值

### 1.1 一句话定义
用户上传**多视图图片**（正/左/右/背/顶/底/45°等）并输入一段**文字描述**，系统把两种模态**融合成同一个条件**，**一次性联合生成一份**几何 + 纹理都符合"图 + 文"双重约束的高质量 3D 模型。

### 1.2 解决什么问题
- **单图生 3D**：背面/底部/被遮挡区域靠模型"脑补"，容易失真。
- **纯文生 3D**：几何整体形态可控，但细节（花纹、材质、比例）难以精准还原用户意图。
- **本方案（图文联合）**：图片负责"看得见的细节还原"，文字负责"全局语义与不可见区域的约束"，两者**同时作为条件**，在一次生成中互相补齐短板；再用一致性自检把偏差定向修正。

### 1.3 与直接堆功能的区别
不是"图生一个模型 + 文生另一个模型再挑一个"，而是把**多视图图像特征与文字特征融合成同一个条件序列**，用 CFG 双模态引导，**一次联合生成一份模型**（图和文同时驱动）。随后用可解释的六维一致性对这**同一份产物**做自检与定向修正。这是本产品的护城河。

> 重要：本方案是**图文同时（联合）生成**，全程只有一份模型。后文的"规格参照"仅用于自检打分，不是第二个交付物。

## 2. 核心概念：图文联合生成 + 一致性自检修正闭环

```
                     ┌──────────────────────────────────────────────┐
                     │                  用户输入                       │
                     │   多视图图片(2~8张)  +  文字描述(prompt)         │
                     └───────────────┬──────────────┬────────────────┘
                    多视图图像编码      │              │   文字编码
                    (DINO/CLIP tokens) │              │  (CLIP text tokens)
                                      └──────┬───────┘
                                             ▼
                          ┌────────────────────────────────────┐
                          │  条件融合：拼接为同一条件序列          │
                          │  CFG 双模态引导 image_scale/text_scale │
                          └────────────────┬───────────────────┘
                                           ▼
                          ┌────────────────────────────────────┐
                          │  Hunyuan3D-DiT + Paint             │
                          │  单次联合去噪 → 一份模型            │
                          │  Model (mesh + texture)            │
                          └────────────────┬───────────────────┘
                                           ▼
                          ┌────────────────────────────────────┐
                          │  一致性自检（对同一份产物打分）        │
                          │  器型/花纹/底部/高度/宽度/材质        │
                          │  参照：输入图像证据 + 文字约束规格     │
                          └────────────────┬───────────────────┘
                                           │ 差异报告 DiffReport
                            ┌──────────────┴──────────────┐
                            │  一致 (所有维度 ≥ 阈值)?       │
                            └──────┬───────────────┬───────┘
                              是 │               │ 否
                                 ▼               ▼
                          ┌──────────┐    ┌───────────────────────────┐
                          │ 输出成品  │    │  定向修正（同一份产物）      │
                          │  Model   │    │  调高该维度文字引导 →         │
                          └──────────┘    │  局部重生成 / 重绘 →          │
                                          │  回到自检 (最多N轮)          │
                                          └───────────────────────────┘
```

**关键设计原则**：
1. **图文同时、单次生成**：图像与文字作为同一条件序列共同驱动一次去噪，产出唯一一份模型；`image_scale/text_scale` 决定两模态相对影响，两者始终同时生效。
2. **自检而非互比**：一致性引擎评估"这一份联合产物是否同时满足图像证据与文字约束"，参照仅用于打分，不作为交付物。
3. **冲突仲裁（§5.4）**：某维度有对应视角图 → 以图像为准（接受）；无图但文字明确 → 提高该维度文字引导做修正。
4. **可解释 + 有界迭代**：每维产出量化分数与证据；修正闭环设最大轮数 N（默认 2~3），并取历史最优防发散。

## 4. 生成流水线（详细流程）

### 4.1 阶段 0 — 输入预处理
- **图片**：去背景（RMBG / SAM 分割主体）→ 归一化尺寸 → 视角识别与标注（哪张是正图/侧图/底图等；用户已在 UI 指定则直接采用）→ 相机位姿估计（用于多视图对齐与后续条件编码）。
- **文字**：意图解析，抽取**结构化约束**（见 §5.1），如从"青花瓷花瓶，细长颈，圈足，缠枝莲纹"抽出 `{类别:花瓶, 材质:陶瓷/青花, 颈:细长, 底:圈足, 纹样:缠枝莲}`。
- 校验：图片数量 2~8（对应 UI 的 Min2/Max8），正图为必填（UI 中"上传正图"带 `*`）。

### 4.2 阶段 1 — 图文联合条件生成（单次，一份模型）
- **条件编码**：多视图图像 → DINO/CLIP 图像 tokens；文字 → CLIP text tokens。
- **条件融合**：把图像 tokens 与文字 tokens **拼接为同一条件序列**，作为 Hunyuan3D-DiT 的 cross-attention 条件。
- **双模态 CFG 引导**：训练/推理时对两种模态各自做独立 dropout，推理用 `image_scale`、`text_scale` 分别控制两模态的引导强度（对应 UI 的模态引导权重）。
- **单次去噪**：一次联合去噪得到形状 latent → 解码为 Mesh；**Hunyuan3D-Paint** 同样以图文联合条件生成 PBR 纹理。
- 产出 `Model = {mesh, texture, 使用的 guidance}`。**这就是唯一交付主体**。

### 4.3 阶段 2 — 一致性自检（核心）
对 `Model` 在 6 大维度逐一评估（详见 §5），参照来自**输入图像证据**（各提供视角的轮廓/CLIP）与**文字约束规格**，输出 `DiffReport`：
```json
{
  "overall": 0.82,
  "dimensions": {
    "shape":    {"score": 0.90, "pass": true,  "authority": "image"},
    "pattern":  {"score": 0.61, "pass": false, "authority": "text",
                 "detail": "产物缺少文字所述缠枝莲纹"},
    "bottom":   {"score": 0.75, "pass": true,  "authority": "image"},
    "height":   {"score": 0.95, "pass": true,  "authority": "image"},
    "width":    {"score": 0.93, "pass": true,  "authority": "image"},
    "material": {"score": 0.58, "pass": false, "authority": "text",
                 "detail": "呈哑光陶土, 文字要求青花釉面高光"}
  },
  "actions": ["repaint_pattern", "adjust_material"]
}
```

### 4.4 阶段 3 — 定向修正闭环（对同一份产物）
- 依据 `DiffReport.actions` 生成**定向修正指令**：
  - 几何类偏差（器型/底部/比例，且无对应视角图）→ 提高该维度文字引导后**局部重生成**。
  - 纹理/材质/花纹类偏差 → 提高文字引导重跑 **Hunyuan3D-Paint** 局部重绘。
- 修正后回到阶段 2 复检；`overall ≥ 阈值` 或达最大轮数 N 则结束，**取历史最优轮**输出。
- **人在环 (Human-in-the-loop)**：每轮把差异报告推给前端，用户可"全部修正 / 只修某几项 / 拒绝并交付当前产物 / 补充文字"。

## 5. 一致性自检的技术实现（各维度指标与算法）

> 所有比对在**统一坐标系与统一尺度归一化**（包围盒对齐 + ICP 配准）后进行，避免摆放/缩放差异误判。

### 5.1 文字约束抽取
用 LLM 把 prompt 解析为结构化 schema，作为自检"标准答案"来源之一：
```
category, material, sub_parts[], patterns[], proportions{h/w/d}, symmetry, color_scheme, style
```
（当前实现为中文关键词启发式，可平滑替换为 LLM few-shot 抽取。）

### 5.2 六大维度评估方法

| 维度 | 中文 | 参照 | 方法 | 输出 |
|------|------|------|------|------|
| shape | 器型 | 图像证据 / 规格 | 多视角轮廓 IoU（对输入图）；Chamfer/体素 IoU（对规格） | 相似度 0~1 |
| pattern | 花纹 | 文字约束 / 输入图 | 多视角渲染做 CLIP 相似度；纹样存在性用 VQA | 分数 + 缺失项 |
| bottom | 底部 | 文字 / 底视图 | 着地区域聚簇 + 着地面积占比 → 平底/圈足/三足/尖底/圆底/底座（§5.6） | 类型匹配度 |
| height | 高度 | 文字数值 / 比例词 / 图 | 有数值规格则按口径互标定比厘米（§5.5），否则归一化 H 比例偏差 | 厘米偏差 / 比例偏差 |
| width | 宽度 | 文字数值 / 图 | 有数值规格则按高互标定比厘米，否则 W 比例偏差；叠加左右对称镜像误差 | 厘米偏差 / 比例偏差 |
| material | 材质 | 文字材质词 | 金属度/粗糙度统计 + 渲染图材质分类 + 光泽意图一致性 | 材质匹配度 |

### 5.3 打分与判定
- 每维度归一到 `[0,1]`，与**可配置阈值**比较得 `pass`。
- `overall = Σ wᵢ·scoreᵢ`（权重按品类可调，如花瓶更看重器型与花纹）。
- 差异附**可视化证据**：并排渲染图、热力差异图、轮廓叠加图。

### 5.4 冲突仲裁（决定偏差时以谁为准）
- **几何维度**（器型/高度/宽度/底部）：**有对应视角图 → 以图像为准**（接受与文字的差异，不强行改动图验证过的几何）；**无图但文字明确 → 提高文字引导做修正**；两者皆弱 → 标"低置信"，提示补图/补文字。
- **绝对尺寸例外**：文字给出了「高 + 口径」这类**数值规格**时，高度/宽度**以文字为准**并触发修正。
  照片没有比例尺，绝对尺寸本就是图像观测不到的量；而正图是必填项，若仍按"有图即以图为准"，
  数值规格将永远无法进入修正闭环（详见 §5.5 尺寸校验）。
- **纹理/材质维度**（花纹/材质）：属表面细节，联合生成常欠还原，偏差一律按约束重绘（目标优先取文字，否则取规格参照）。

### 5.5 数值尺寸校验（把"17.5 公分"变成可判定的量）
文物描述常自带尺寸，如「高17.5、口径16.5公分」。抽取时统一折算为厘米（支持
厘米/公分/cm/毫米/mm/米/m，缺省按厘米；「公元前711年」这类无尺寸前缀的数字不计入）。

校验方式是**互标定**而非直接比大小——生成结果没有绝对尺度，先用其中一个尺寸把产物
标定到真实世界，再核对另一个：
- 高度：按口径标定 → `实测高 = H/W × 口径`，与目标高比较；
- 宽度：按高标定 → `实测口径 = W/H × 高`，与目标口径比较。

于是报告给出的是「目标 17.5cm，实测 ≈ 19.0cm，偏差 8%」这类可读结论，
而不是两个归一化常数的自比。

### 5.6 底部形态的真实测量
底部维度支持 **平底 / 圈足 / 三足 / 多足 / 尖底 / 圆底 / 底座** 七类，全部在网格上直接测量，
不依赖生成侧自报：
1. 取最低平面附近的**着地点集**，按方位角聚簇 → 簇数即足数（3 簇 = 三足）；
2. 着地点中心悬空（最小半径 / 外接半径 > 0.12）→ 圈足；
3. **着地面积占比**（朝下且贴地的面积 / 外接圆面积）近 0 → 尖底或圆底，
   再按半径随高度张开的快慢区分（球冠张得快、锥尖张得慢）；
4. 着地盘比器身更外扩 → 底座，否则平底。

形态不匹配时按物理接近度打分（平底↔底座、尖底↔圆底属近似），而非一律判最低分。

### 5.7 坐标轴约定
内部一切几何度量按 **Z 轴朝上**（trimesh 约定）；**交付文件（GLB/OBJ）导出时转为 +Y 朝上**，
以符合 glTF 规范——Blender 的 glTF 导入同样按 +Y 换算。若不转换，模型在网页预览器与
50 视角渲染里会全部侧躺。

### 6.1 相比原截图新增/变化
1. **文字描述输入框**（必要）：与多视图上传并列，两者**同时作为生成条件**；提供示例词、字数提示、结构化标签联想。
2. **模态引导权重**：图像引导更强 / 图文均衡 / 文字引导更强，映射到 CFG 的 `image_scale/text_scale`（§2 原则 1）。
3. **一致性阈值 & 最大修正轮数**：暴露给高级用户，控制质量与成本。
4. **生成中/生成后**：分阶段进度（联合生成 → 自检 → 修正第k轮）；**差异报告面板**（六维 + 证据 + 接受/拒绝/局部修正）；3D 预览与下载 `glb/obj`。

### 6.2 交互流（时序）
```
用户: 传图(≥2, 含正图) + 写文字 + 选模态引导 → 点"立即生成"
系统: 建任务 → WS推进度
  → [预处理] 文字约束抽取
  → [联合生成] 图+文同时 → 一份模型   进度 20~55%
  → [自检]   六维一致性 + 弹差异报告(可暂停等用户/自动继续)
  → [修正×k] 定向重生成/重绘           进度 55→95%
  → 完成 100% → 预览 + 下载
```

## 7. API 设计

### 7.1 创建生成任务
```http
POST /api/v1/generation
```
```json
{
  "images": [
    {"view": "front", "url": "...", "required": true},
    {"view": "left45", "url": "..."},
    {"view": "bottom", "url": "..."}
  ],
  "prompt": "青花瓷花瓶, 细长颈, 圈足, 缠枝莲纹, 釉面高光",
  "model_version": "hunyuan3d-v3.1",
  "face_count": "1.5m",
  "fusion": {
    "strategy": "image_primary",      // image_primary | balanced | text_correct
    "consistency_threshold": 0.8,
    "max_refine_rounds": 2,
    "dimension_weights": {"shape":0.3,"pattern":0.2,"bottom":0.1,
                          "height":0.1,"width":0.1,"material":0.2}
  },
  "human_in_loop": false
}
```
`strategy` 在服务端映射为双模态引导 `guidance = {image_scale, text_scale}`（图与文同时生效）。

## 8. 技术栈与部署

| 层 | 选型建议 |
|----|----------|
| 前端 | React/Vue + Three.js（预览）；ECharts（六维雷达图） |
| BFF/API | Python(FastAPI) 或 Node.js(NestJS) |
| 编排 | Temporal / Celery + 状态机（预处理→联合生成→自检→修正循环） |
| 推理 | 混元 3D（条件编码 + DiT + Paint）自托管 GPU 集群；文字/图像编码器复用同栈 |
| 自检 | CLIP/DINOv2（特征）、VQA/LLM（纹样/材质语义）、Open3D/trimesh（几何 Chamfer/IoU/ICP/包围盒）、Blender/自研渲染出多视角图 |
| 存储 | S3/OSS（图与 mesh）、PostgreSQL（元数据/任务）、Redis（缓存/队列）、向量库(可选) |
| 观测 | 链路 tracing、每阶段耗时/成功率、每维度分数分布（用于调阈值/权重） |

## 9. 任务状态机

```
queued → preprocessing → generating(图文联合,单次) → verifying →  pass? ─是→ done
                                                        │
                                                        否
                                                        ▼
                                           (human_in_loop?) ─是→ awaiting_user →(决策)
                                                        │否
                                                        ▼
                                                    refining → verifying
                                     (round < N 且 未pass 则循环; 否则取历史最优 → done)
failed  (任意阶段异常且重试耗尽)
```

## 10. 里程碑 / 迭代计划

- **M1 MVP（已实现）**：图 + 文输入 UI；图文联合生成（Mock 适配器，无 GPU 可跑）；六维自检（几何维度真实测量）；定向修正闭环收敛；输出 glb + 3D 预览。
- **M2 接入真实混元 3D**：条件融合 + 双模态 CFG 引导落地；CLIP/VQA 花纹检测、PBR 材质分析；六维雷达图与证据可视化；人在环。
- **M3 修正智能化**：局部几何重生成、冲突仲裁规则引擎、按品类自动配权重与阈值。
- **M4 体验与规模化**：缓存复用、成本与时延优化、批量/API 开放平台。

## 11. 风险与对策

| 风险 | 说明 | 对策 |
|------|------|------|
| 联合条件需模型支持 | 原生 Hunyuan3D 以图像条件为主，文字联合需适配器/微调 | 训练文字条件 adapter + 双模态 CFG；过渡期文字可经语义约束注入 Paint 与几何修正 |
| 自检误判导致错误修正 | 尺度/坐标未对齐、语义判定不准 | 强制归一化+ICP；语义维度双模型投票；低置信项交人工 |
| 修正发散 | 越修越偏 | 有界轮数 N；记录每轮 overall，取历史最优轮输出 |
| 图文本质冲突 | 用户图文描述不一致 | 显式冲突提示 + 模态引导权重让用户选主导方 |
| 底/背视缺失 | 用户未传全视角 | 提高该区域文字引导补全，并在报告中标注"该区域为推断" |
| 成本 | 联合生成 + 多轮修正 GPU 成本 | 阈值高时早停；纹理类修正只重跑 Paint 不重跑几何；缓存条件编码 |
