# 生产部署指南

本项目分两部分：**主服务**(编排/自检/前端，CPU 即可) 与 **混元桥接服务**(GPU)。
下面给出到"生产可用"的配置、清单与仍需你在硬件上验证的部分。

---

## 1. 组件拓扑

```
             ┌────────────┐        ┌─────────────────────┐
浏览器 ─────►│ 反向代理     │ ─────► │ 主服务 to3d (CPU)    │
  HTTPS      │ (nginx/traefik)│      │ FastAPI + 前端       │
             │ TLS/限流/WAF  │       │ 编排·自检·任务队列    │
             └────────────┘        └──────────┬──────────┘
                                    TO3D_ADAPTER=http │
                                                      ▼
                                        ┌─────────────────────┐
                                        │ 混元桥接 (GPU)        │
                                        │ hunyuan_server.py    │
                                        │ DiT+Paint+CLIP+渲染   │
                                        └─────────────────────┘
```

---

## 2. 主服务：生产配置

**必须设置**（见 `.env.example` 全量）：
```bash
TO3D_ADAPTER=http
TO3D_HUNYUAN_ENDPOINT=http://hunyuan-gpu:9000
TO3D_API_KEY=<强随机串>            # 启用鉴权
TO3D_ALLOWED_ORIGINS=https://your-domain.com
TO3D_DB_URL=sqlite:////data/to3d.db   # 单机持久化；多副本见 §4
TO3D_OUTPUT_DIR=/data/outputs
TO3D_MAX_CONCURRENCY=2             # 匹配 GPU 并发能力
TO3D_TASK_TTL_SECONDS=3600
```

**启动**（单进程；因进度广播/决策在进程内，勿用多 worker，见 §4）：
```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000
# 或容器： docker compose up --build
```

**探针**：
- 存活 `GET /api/health`，就绪 `GET /api/ready`，指标 `GET /metrics`(Prometheus)。

**反向代理**（生产必做）：TLS 终止、按 IP/Key 限流、请求体上限、超时、把 `/metrics`
仅对内网开放。示例(nginx)：`client_max_body_size 64m; proxy_read_timeout 900s;`

## 3. 混元桥接服务（GPU）

见 [`serving/README.md`](../serving/README.md)。要点：
```bash
docker build -f serving/Dockerfile -t to3d-hunyuan serving
docker run --gpus all -p 9000:9000 -v /data/hf:/data/hf to3d-hunyuan
```
- 显存：形状 ≥12GB；开纹理 ≥16–24GB；A6000(48G)/5090(32G) 皆可，笔记本一般不够。
- 内置 SSRF/LFI 防护(`HY3D_BLOCK_PRIVATE_IPS`/`HY3D_ALLOW_LOCAL_FILE`)。
- 纹理/材质分析(CLIP+渲染+PBR)默认开启，可用 `HY3D_TEX_ANALYZER=prompt` 关闭。

---

## 4. 水平扩展（多副本）

主服务当前用**进程内**进度广播与任务并发信号量，且默认 SQLite 单机持久化，因此：
- **单副本**：直接可用（推荐起步；瓶颈在 GPU 而非主服务）。
- **多副本**：需替换三处外部依赖——
  1. **状态存储**：把 `TO3D_DB_URL` 指向 PostgreSQL（实现 `BaseTaskStore` 的 PG 版，
     接口已抽象，改动集中在 `app/store.py`）。
  2. **进度广播 / 决策**：改用 Redis pub/sub（替换 `_PubSub`）。
  3. **任务分发 / GPU 调度**：引入 Celery/Temporal + GPU worker 池，`run_generation`
     改为投递任务；这样进程重启也能续跑（当前实现重启会丢失在飞任务）。

架构已按可替换设计（适配器/存储/编排均解耦），上述为纯基础设施接入，无需改业务逻辑。

## 5. 上生产前检查清单

- [ ] 主服务：设置 `TO3D_API_KEY`、`TO3D_ALLOWED_ORIGINS`、`TO3D_DB_URL`、`TO3D_OUTPUT_DIR`。
- [ ] 反向代理：TLS、限流、`client_max_body_size`、超时；`/metrics` 仅内网。
- [ ] 桥接服务：GPU 就绪，`/health` 通过；显存满足纹理需求。
- [ ] **端到端联调**：`TO3D_ADAPTER=http` 下前端真跑一单，产物与六维报告正常。
      （这是唯一必须在 GPU 硬件上验证的环节；沙箱/CI 无法覆盖。）
- [ ] 监控：抓取 `/metrics`(生成计数/耗时/在飞)，接入告警。
- [ ] 备份：`TO3D_OUTPUT_DIR` 与 DB 落在持久卷；确认 TTL 清理符合留存策略。
- [ ] 压测：按目标 QPS 与 GPU 并发核对 `TO3D_MAX_CONCURRENCY` 与排队时延。
